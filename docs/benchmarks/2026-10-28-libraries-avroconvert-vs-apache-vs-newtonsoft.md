# AvroConvert 4.0 vs Apache.Avro vs Newtonsoft.Json

The same dataset (`User` with nested `Contact` and two `Offering`s) serialized to / deserialized from a `byte[]` by each library. Source: `benchmarks/LibrariesBenchmark`, chart: `libraries.png`, re-render with `scripts/plot-libraries.py`.

How each library is driven:

| Library | Version | Write | Read |
|---|---|---|---|
| AvroConvert | 4.0.0-preview.3 | `AvroConvert.Serialize(List<User>)` – Avro container file, one entry per record, codec `null` | `AvroConvert.Deserialize<List<User>>` |
| Apache.Avro | 1.12.2 | classes generated by `avrogen` from `Specific/user.avsc` (`ISpecificRecord`, the way the Confluent Schema Registry serdes use Apache.Avro); `SpecificDatumWriter<User>` + `DataFileWriter<User>` – Avro container file, one entry per record, codec `null` | `DataFileReader<User>` (specific reader) |
| Newtonsoft.Json | 13.0.4 | `JsonSerializer` → `JsonTextWriter` → UTF-8 bytes | `JsonTextReader` → `JsonSerializer.Deserialize<List<User>>` |

The binary data of AvroConvert and Apache.Avro is byte-identical and AvroConvert reads the Apache.Avro file (checked by `dotnet run -- smoke`). The Apache.Avro file is 27 B larger: the generated classes are in the `LibrariesBenchmark.Specific` namespace, which the container header names.
