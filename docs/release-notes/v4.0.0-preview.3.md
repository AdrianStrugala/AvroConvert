The third 4.0 preview adds a command line tool and makes serialization about 2 times faster. Please try it on your data and report anything that behaves differently than 3.4.x or the previous previews.

```
dotnet add package AvroConvert --prerelease
dotnet tool install --global SolTechnology.Avro.Cli --prerelease
```

## SolTechnology.Avro.Cli

A .NET tool, `avroconvert`. The commands are named like in Apache avro-tools:

```
avroconvert induce      bin/Release/net10.0/MyApp.dll MyApp.Contracts.Order
avroconvert compile     schema order.avsc src/Generated
avroconvert tojson      data.avro --pretty --head
avroconvert getschema   data.avro
avroconvert fingerprint order.avsc
avroconvert compat      v1.avsc v2.avsc --mode Backward
avroconvert registry test --subject orders-value --assembly bin/Release/net10.0/MyApp.dll --type MyApp.Contracts.Order
```

Exit code 1 when schemas are not compatible, so `compat` and `registry test` can stop a build. Details: [Documentation.Cli.md](https://github.com/AdrianStrugala/AvroConvert/blob/master/docs/Documentation.Cli.md).

## Core

- Serialization is about 2 times faster and allocates 5 times less: 1 000 records take 136 μs instead of 272 μs and 133 KB instead of 707 KB. One message without a container (the Kafka case): 119 ns instead of 219 ns.
- Deserialization: one message without a container about 30 % faster (198 ns instead of 278 ns), 1 000 records about 15 % faster.
- Recursive types (`Node Next`, `List<Node> Children`) get a schema; 3.x and the previous previews failed with "Maximum depth of object graph reached".
- **Behaviour change:** read objects are created with their public parameterless constructor, like System.Text.Json does. A field that is missing from the data keeps its initialiser (`List<string> Tags { get; set; } = new()` stays an empty list instead of `null`).
- A declared licence is checked once per process, not on every call.
- The licence notice for an invalid key points to contact@soltechnology.dev.
- The NuGet icon has a white background.
