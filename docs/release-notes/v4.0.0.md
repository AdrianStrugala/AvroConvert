AvroConvert 4.0 is rewritten for .NET 10 and follows the Avro 1.12 specification end to end. It reads and writes the same data as Apache.Avro, Confluent and Chr.Avro, and comes with a CLI and a rewritten Kafka package.

```
dotnet add package AvroConvert
```

## Highlights

- Serialization compiled once per type and schema: several times faster than 3.4.x, fewer allocations.
- Streaming: `Serialize<T>(IEnumerable<T> / IAsyncEnumerable<T>, Stream)`, `Deserialize<T>(Stream)` → `IAsyncEnumerable<T>`, `IBufferWriter<byte>`.
- `AvroSchema`: parse, create from a class or from data, canonical form, fingerprints, `Compare`, `CheckCompatibility`.
- Data without a class: `dynamic`, `ExpandoObject`, `Dictionary<string, object>`, unions of records.
- Avro JSON Encoding (`Avro2JsonEncoding` / `JsonEncoding2Avro`), zstandard, `timestamp-nanos`, `local-timestamp-*`, `big-decimal`, `uuid` on `fixed`.
- `GenerateModel` classes give back the source schema.
- New CLI: `dotnet tool install --global SolTechnology.Avro.Cli` (`induce`, `compile`, `tojson`, `canonical`, `fingerprint`, `compat`, `registry`).
- SolTechnology.Avro.Kafka on Confluent.SchemaRegistry 2.16: wire format, schema evolution, references, subject name strategies.

## Breaking changes

- Requires **.NET 10**. For .NET Framework and .NET 6–9 use 3.4.x (`release/3.x`, security and critical fixes).
- Collections are written as one container entry per item (`CollectionMode = SingleArray` for the old layout); 3.x files are still read.
- A missing non-nullable field throws (`MissingFieldHandling = UseDefault` for the old behaviour).
- Writing `null` into a non-nullable field throws (`NullValueHandling = WriteEmpty` for the old behaviour).
- `SchemaConvert` is replaced by `AvroSchema`.
- Code compiled against a 4.0 preview must be rebuilt.

Full list: [CHANGELOG](https://github.com/AdrianStrugala/AvroConvert/blob/master/docs/CHANGELOG.md)
