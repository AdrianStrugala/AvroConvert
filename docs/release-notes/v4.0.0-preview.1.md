The core is rewritten for .NET 10, the library follows the Avro 1.12 specification end to end, and the licence changes. Stable 4.0.0 is planned for mid-November. Please try it on your data and report anything that behaves differently than 3.4.x.

```
dotnet add package AvroConvert --prerelease
```

## Highlights

- Serializers compiled once per type and schema. Compared to 3.4.17 on the same data: reading 1 000 records 8× faster with 5× less memory, writing 2× faster.
- Streaming API: `Serialize<T>(IEnumerable<T>, Stream)`, `Serialize<T>(IAsyncEnumerable<T>, Stream)`, `Deserialize<T>(Stream)` → `IAsyncEnumerable<T>`, and `IBufferWriter<byte>` overloads.
- `AvroSchema`: canonical form, fingerprints, `Compare` and `CheckCompatibility` (Backward / Forward / Full, transitive).
- Avro JSON encoding: `Avro2JsonEncoding` / `JsonEncoding2Avro`, avro-tools compatible.
- Unions of records, `ExpandoObject`, headless `dynamic`, zstandard codec, `timestamp-nanos`, `local-timestamp-*`, `uuid` on `fixed(16)`.

## Breaking changes

- Requires **.NET 10**. 3.4.x stays on `release/3.x` with security and critical fixes.
- Collections are written as one container entry per element (`CollectionMode = SingleArray` for the old layout).
- A missing field that can't be `null` throws (`MissingFieldHandling = UseDefault` for the old behaviour).
- Writing `null` into a field whose schema can't hold `null` throws (`NullValueHandling = WriteEmpty` for the old behaviour).
- Generated schemas change for generic types, private `[DataMember]` members and `time-micros`.
- `SchemaConvert` is replaced by `AvroSchema`.

Full list: [CHANGELOG](https://github.com/AdrianStrugala/AvroConvert/blob/master/docs/CHANGELOG.md)
