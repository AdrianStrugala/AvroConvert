The second 4.0 preview rewrites the Kafka and HTTP packages on top of the 4.0 core, fixes JSON schema inference, and moves AvroConvert Online to [soltechnology.dev/avroconvert/online](https://soltechnology.dev/avroconvert/online/). Please try it on your data and report anything that behaves differently than 3.4.x or preview.1.

```
dotnet add package AvroConvert --prerelease
dotnet add package SolTechnology.Avro.Kafka --prerelease
dotnet add package SolTechnology.Avro.Http --prerelease
```

## SolTechnology.Avro.Kafka

Rewritten on the Confluent.SchemaRegistry serializer base classes (Confluent.Kafka / SchemaRegistry 2.16). Messages are in the real Confluent wire format, readable and writable by the Confluent serializers of Java, Python, Go and .NET. This is verified against the official Confluent Avro serdes and against a real broker and Schema Registry.

```csharp
using var schemaRegistry = new CachedSchemaRegistryClient(new SchemaRegistryConfig { Url = "http://localhost:8081" });

var producer = new ProducerBuilder<string, Order>(config).SetAvroValueSerializer(schemaRegistry).Build();
var consumer = new ConsumerBuilder<string, Order>(config).SetAvroValueDeserializer(schemaRegistry).Build();
```

- Subject name strategies, auto-registration, use latest version / schema id, and the schema id in the prefix or in a message header.
- Schema references (types shared through their own subjects), schema evolution against the schema of `T`, and tombstones.
- `AvroConvertOptions` (naming policy, converters) flow through to the schema and the data.

## SolTechnology.Avro.Http

- **HttpClient:** `GetFromAvroAsync` (sends `Accept: application/avro`), `PostAsAvroAsync`, `PutAsAvroAsync`, `PatchAsAvroAsync`, `ReadFromAvroAsync`, `AvroContent`.
- **MVC:** `AddControllers().AddAvroFormatters(options)`. A body that is not valid Avro is a 400.
- **Minimal APIs:** `Avro<T>` request bodies and `AvroResults.Avro(value)` / `Results.Extensions.Avro(value)`.
- **Streaming in both directions:** `AvroResults.Stream(IAsyncEnumerable<T>)`, `AvroStream<T>` request bodies, `GetFromAvroAsAsyncEnumerable<T>` and `PostAsAvroStreamAsync`. Data blocks go out as soon as they are full.

## Core

- `AvroSchema.Parse(json, referencedSchemas)` for schemas that use named types from other schemas.
- Writing with a schema that has a field your class does not have writes the field's `default`, for example a newer version from a registry.
- `Json2Avro` / `AvroSchema.InferFromJson` look at every element of a JSON array:
  - a field that is null or missing in some elements becomes nullable (preview.1 threw);
  - `0` followed by `1.5` becomes `double` (preview.1 inferred `long` and truncated the fraction).
- New overloads: `Deserialize(byte[], Type, AvroConvertOptions)` and `DeserializeHeadless<T>(ReadOnlySpan<byte>, AvroSchema, AvroSchema, AvroConvertOptions)`.
- Exact dependency versions: Newtonsoft.Json 13.0.4, IronSnappy 1.3.1, ZstdSharp.Port 0.8.8.

## Breaking changes since preview.1 / 3.x packages

- **Kafka:** `AvroConvertSerializer<T>` / `AvroConvertDeserializer<T>` (without a registry) now take an `AvroSchema` and write plain headless Avro. 3.x wrote a fake Confluent header with schema id 0.
- **Kafka:** `KafkaConsumer`, `KafkaPropNames`, `ConfluentSchema` and `SetAvroValueDeserializer(string)` are removed. Use the builder extensions above.
- **Http:** `GetAsAvro`, `PostAsAvro`, `PutAsAvro`, `PatchAsAvro` and `Consts` still work but are `[Obsolete]`. Use the `…Async` methods and `AvroMediaTypes`.

## AvroConvert Online

[soltechnology.dev/avroconvert/online](https://soltechnology.dev/avroconvert/online/) runs AvroConvert in your browser (WebAssembly). Nothing is uploaded. It has five tools:

- schema → C#
- Avro file viewer
- JSON → Avro with a size comparison
- schema compatibility checker
- Kafka message decoder
